## 已解决

- [x] #1 · 2026-09-20 · Series 的用法不熟：`.rolling`、`.mean`、`.round` 这些到底是 Series 的方法，还是 pandas 的函数？

  → 答案（2026-09-22）：根子上是没分清 **方法 method** 和 **函数 function**。

  - **方法**：依附在某个对象上。`s.mean()`、`s.rolling(window=5)`、`s.round(2)` —— 点号前面那个，就是它服务的对象。
  - **函数**：直接调用，比如 `pd.concat(...)`。有的是 Python 库里自带的，有的是我自己用 `def` 写出来的。
  - 所以 `s.rolling(window=5)` 是**先造出一个「滚动窗口」对象**，再对这个新对象调 `.mean()`。一行里连着调好几个方法，这叫**链式调用**。

- [x] #5 · 2026-09-21 · `np.array` 这个函数不懂怎么用，像魔法一样就用出来了

  → 答案（2026-09-22）：底层是我没分清 **列表 / 数组 / 元组**。

  - **列表** `list`：有序、可变（元素值和长度都能改），能装各种类型的对象。靠指针指向每一个独立对象。
  - **数组** `ndarray`：有序、**元素值可变但长度固定**、所有元素类型必须统一。是一整块同类型的数值，所以算得快、省内存。
  - **元组** `tuple`：有序、不可变（元素值和长度都改不了），其余和列表差不多。

  放到代码里：`np.array(cumulative)` 就是把列表 `cumulative` 转成数组，于是 `100 + np.array(cumulative)` 才能把 100 逐个加到每个元素上。
  一句话：`np.array` 只是个**类型转换器**；转换完之后的向量化运算，是数组对象本身提供的。

- [x] #7 · 2026-09-21 · `(100 + np.cumsum(steps)).round(2)` 的逻辑看不懂：为什么一个数字加上这条路径就能生成随机行走？一个数字加一个数组吗？

  → 答案：NumPy 的**广播**（broadcasting）。标量 `100` 会先被扩展成和 `np.cumsum(steps)` 形状相同的数组（500 个 100），再逐元素相加。所以 `100 + [0.3, -0.4, ...]` 得到 `[100.3, 99.6, ...]`。
  → `cumsum` 是逐日累加：第 i 个元素 = 前 i+1 个增量之和。所以「随机游走」= 起点 100 + 一路累积的随机增量。
  → 一行验证：`(100 + np.cumsum(steps))[i] == 100 + steps[:i+1].sum()`。
